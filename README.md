# Foodfolio

メニュー（辞典）を埋めながら、地域の飲食店とユーザーを繋ぐプラットフォーム。

飲食店が全メニューを「**辞典**」として登録し、ユーザーは実際に来店・注文したメニューを「**カード**」として集めて辞典を埋めていく。“ご当地グルメ図鑑” のような収集体験で、来店と**認知**を同時に促進する。

---

## 背景・前提

- **開催**: 会津で開催されるハッカソン（テーマ: **「会津の食」**）
- **視点**: 大学生の目線から課題を抽出
- **ペルソナ**:
  - 会津の飲食店
  - 会津の学生
- **課題**:
  - 飲食店 → 学生に**認知されていない**
  - 学生 → 会津の飲食店を**知らない**
- **解決の方向性**: 認知の入口を作りつつ、収集ゲーム体験で継続利用を促す
- **地域資産の活用**: 会津コイン（会津地域で流通する電子マネー）と連動し、飲食業界を盛り上げる

---

## コアコンセプト

- 飲食店は **辞典（= 全メニューを登録したもの）** を作成する
- ユーザーは辞典を導入している店を訪れ、注文したメニューの **カード** を作成して辞典を埋めていく
- 店が設定した **グループ** のカードを集めきると、**クーポン**（会津コイン連動）が発行される
- **マップ**で辞典導入店を可視化し、認知の入口にする

> 収集（図鑑埋め）× 来店インセンティブ（クーポン）× 発見（マップ）で、
> 「知らない店を知り、行き、集める」体験を作る。

### 登録の仮条件

- 飲食店は **会津コイン導入** を条件にプラットフォームへ登録する

---

## 機能一覧

### 飲食店側

- **辞典作成ページ**: メニューを登録して辞典を作成する
- **グループ / クーポン作成ページ**: メニューをグループ化し、達成時に発行するクーポンを設定する

### ユーザー側

- **マップ機能**: 現在地周辺の辞典導入店を地図で探索（= 認知の入口）
- **辞典一覧ページ**: 店ごとの辞典を閲覧し、自分の収集状況を確認する
- **カード作成**: 注文したメニューをカード化し、辞典を埋める
- **クーポン表示ページ**: 会津コイン連動クーポンを表示する

---

## グループ & クーポンの仕組み

**グループ** は店側が作るメニューの括り。グループ内のカードをユーザーが全て集めると、クーポンが発行される。

- 例1: **「塩ラーメングループ」** … 店の塩ラーメン全種を集めるとクーポン
- 例2: **「当店のおすすめグループ」** … おすすめメニューを集めるとクーポン

```
グループ（店が定義） = メニューの集合
        ↓ ユーザーがグループ内の全カードを作成
    クーポン発行（会津コイン連動）
```

## データモデル（下書き）

```
店舗(Restaurant) ──< メニュー(MenuItem) >── カード(Card) >── ユーザー(User)
   │                      │
   │                      └─< グループ(Group) ──> クーポン(Coupon)
   └─ 位置情報(緯度経度) → マップの「近くの店」検索に使用
```

| エンティティ | 説明 |
|---|---|
| **Restaurant（店舗）** | 飲食店。位置情報（緯度経度）を持つ |
| **MenuItem（メニュー）** | 店舗に属する個々のメニュー。辞典の構成要素 |
| **辞典** | ある店舗のメニュー集合（≒ 店舗そのものに紐づく） |
| **Group（グループ）** | メニューの括り（例: 塩ラーメン、おすすめ）。クーポンの達成条件 |
| **Card（カード）** | ユーザー × メニュー の「食べた記録」 |
| **Coupon（クーポン）** | グループ完成でアンロックされる特典（会津コイン連動） |
| **User（ユーザー）** | 学生などの利用者 |

## 技術スタック

| レイヤー | 技術 | 補足 |
|---|---|---|
| **フロントエンド** | **Flutter** | Web ファースト → 将来モバイル（iOS/Android）へ 1 コードベースで拡張 |
| **地図** | **flutter_map**（OpenStreetMap タイル） | Web / モバイル両対応・無料。カスタムピンで辞典導入店を表示 |
| **バックエンド / DB** | **Supabase** | Postgres + Auth + Storage + Realtime |
| **地理空間検索** | **PostGIS**（Supabase） | 「現在地から半径 N km の辞典導入店」を `ST_DWithin` で検索 |
| **画像** | **Supabase Storage** | メニュー写真・カード画像の保存 |

### 選定理由

- **Flutter**: 1 コードベースで **Web + モバイル（ネイティブ）** を実現できる。既存の連携先 Flutter アプリとの **コード共有・将来統合** もしやすい。
- **Supabase**: 認証・DB・ストレージ・リアルタイムが一式揃い、ハッカソンの開発速度に合う。
- **地図の「近くの店検索」はバックエンド（PostGIS）が担当**し、地図ライブラリは結果をピン描画するだけ。この構造により地図機能はシンプルに実装できる。

```
Supabase(PostGIS) で現在地から半径内の店を ST_DWithin 検索
        ↓ 店リスト(緯度経度)を返す
flutter_map が店をピンとして地図に描画 → タップで辞典ページへ
```

### トレードオフ（認識しておく点）

- Flutter Web は SEO / 初期ロードがやや弱い。認知を Web 検索・SNS 共有でも取りたくなった場合は、**認知用の軽量ランディングページ（店舗ページ）を別途用意**して補う方針で吸収する。

---

## スコープ（ハッカソン版）

- **会津コイン連携**: ハッカソンでは **クーポンの表示（コード / QR 表示）まで** を実装する。
  実際の決済は店舗の既存コイン端末に任せ、決済 API の直接連携は対象外とする（提供元との提携が前提になるため）。

## 開発環境のセットアップ

### 前提ツール

| ツール | 用途 |
|---|---|
| **Docker Desktop** | ローカル Supabase の実行基盤（起動しておくこと） |
| **Supabase CLI** | ローカルDB起動・マイグレーション適用 |
| **Flutter SDK** | フロントエンド開発 |

### ディレクトリ構成（バックエンド）

```
supabase/
├── config.toml             # ローカルスタック設定（analytics は無効化済み）
├── migrations/
│   ├── 0001_init.sql       # スキーマ本体（テーブル/関数/トリガー/RLS/Storage）
│   └── 0002_owner_rpcs.sql # 店舗オーナー向けRPC（位置情報つき作成/取得）
└── seed.sql                # デモ用サンプルデータ
```

### ローカル Supabase の起動

```bash
supabase start   # 初回はDockerイメージDLで数分かかる
```

起動すると以下のローカル接続情報が表示される（ローカル専用の固定値で、本番キーとは別物）：

| 項目 | 値 |
|---|---|
| Studio（管理画面） | http://127.0.0.1:54323 |
| Project URL（API） | http://127.0.0.1:54321 |
| DB URL | postgresql://postgres:postgres@127.0.0.1:54322/postgres |
| Mailpit（確認メール受信） | http://127.0.0.1:54324 |

`supabase start` 時に `migrations/` と `seed.sql` が自動適用される。

### よく使う操作

```bash
supabase status      # 起動状況・URL・キーの再表示
supabase stop        # 停止（データは保持）
supabase start       # 再開
supabase db reset    # マイグレーション＋seedを最初からやり直す（DB初期化）
```

### デモデータ（seed）について

`seed.sql` は「最初に登録された auth ユーザーをオーナーにする」設計。ユーザーが0人だとスキップされる。
データを入れるには、Studio の Authentication もしくはアプリのサインアップでユーザーを作ってから `supabase db reset` を実行する。

### アプリ（Flutter）の起動

Web（Chrome）で起動する（既定でローカル Supabase に接続）：

```bash
flutter pub get          # 初回・依存更新時
flutter run -d chrome
```

別環境の Supabase に接続する場合は `--dart-define` で上書き：

```bash
flutter run -d chrome \
  --dart-define=SUPABASE_URL=https://xxxx.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=sb_publishable_xxxx
```

#### フロントエンド構成（`lib/`）

```
lib/
├── main.dart                 # エントリ。Supabase 初期化 → アプリ起動
├── core/
│   ├── env.dart              # 接続設定（--dart-define で上書き可）
│   └── supabase.dart         # Supabase クライアントのショートカット
├── app/
│   └── router.dart           # go_router（下部ナビ: マップ/辞典/クーポン/店舗 ＋ 認証ガード）
└── features/
    ├── auth/                 # ログイン/サインアップ・ログアウト
    ├── shell/                # 下部ナビのシェル
    ├── map/                  # マップ（現在地取得 + flutter_map + nearby_restaurants RPC）
    ├── dictionary/           # 辞典一覧・詳細（収集状況/グループ進捗）
    ├── cards/                # チェキ風カード（写真＋白フレーム＋マッキー風コメント）
    ├── coupons/              # クーポン表示（発行済みクーポン）
    └── owner/                # 店舗側: 店舗登録・メニュー管理・グループ/クーポン作成
```

### 本番（クラウド）への反映

ローカルで固めたら、supabase.com でプロジェクトを作成し、以下でスキーマを反映する：

```bash
supabase link --project-ref <your-project-ref>
supabase db push
```
