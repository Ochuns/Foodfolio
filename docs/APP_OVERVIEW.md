# Foodfolio — アプリ概要（AI共有用サマリー）

> このドキュメントは、画像生成AIや他のAIに「Foodfolio とはどんなアプリか」を理解させるための自己完結した説明書です。
> UI改訂・ビジュアル生成の指示を出す前に、まずこれを読ませることを想定しています。

---

## 1. 一言で言うと

**会津（福島県・会津地方）のご当地グルメを「食べて集める」フォトコレクションアプリ。**
ユーザーは飲食店で料理を注文し、その場で **「チェキ」（インスタント写真風のカード）** を撮影・収集する。
店舗ごとの料理が **「辞典（食事典）」** という一冊の本にまとまっており、ページをめくって集めていく。
特定のメニューの組み合わせ（＝**グループ**）を自分のチェキで揃えると、**クーポン（会津コイン連携）** がもらえる。

コンセプトのモチーフは **「妖怪ウォッチの妖怪大辞典」**。図鑑をコンプリートしていく収集の楽しさを、ご当地グルメ×地域通貨（会津コイン）と結びつけている。ハッカソン作品。

## 2. 世界観・テーマ（画像生成で最重要）

- **古い図鑑・百科事典（辞典）** の world。革張りの分厚い本、クリーム色の古紙、金の装飾枠。
- **チェキ＝インスタントフォト（instax / ポラロイド風）**。正方形の写真＋下に広い白フレーム＋手書き風コメント＋日付スタンプ。
- 和の温かみ。手書き風フォント（Google Fonts **Yusei Magic**）でコメントを描く。
- 「封印された伝説のページ（レジェンド封印妖怪）」のメタファーで、**グループ（コンプ対象）は辞典の最後のページ**に置かれる。

## 3. 中心的オブジェクト

### 3-1. チェキ（ChekiCard）= このアプリの主役ビジュアル
インスタントフォト（instax mini 風）を模したカード。

構成（上から下）：
1. **正方形の写真**（料理の写真）
2. 下の**白いフレーム**部分に:
   - 星評価（★1〜5、amber色）
   - **手書き風コメント**（中央、Yusei Magic、最大2行）
   - 右下に**撮影日スタンプ**（例 `2026.10.29`、オレンジ色）
3. カード全体はわずかに回転（±0.02〜0.03 rad）して無造作に置かれた雰囲気。白地＋ドロップシャドウ。

**状態バリエーション（重要）**：
- **未使用（通常）**：左下角に**黒い破線（ミシン目＝切り取り線）**が描かれる。「ここで切れるよ」の予告。
- **使用済み（クーポンに使った）**：左下角が**切符のように斜めにカット（切り込み）**される。写真は隠さない。フレーム右上に小さな赤枠の **「使用済」タグ**。
- **未収集スロット（プレースホルダー）**：コメントが **「？」** のチェキを半透明（opacity 0.45〜0.5）で表示。「まだ集めてない枠」を示す。切り取り線は出さない。

> デザイン意図：クーポンに使ったチェキは「切符にハサミが入った」ように**物理的な消費の痕跡**を残すが、思い出の写真は消さない。

### 3-2. 辞典（食事典）= 店舗1つ＝本1冊
- **一覧画面**：店舗が「閉じた革張りの本（辞典）の表紙」として本棚のように並ぶ。表紙は濃茶グラデ＋金枠、上部に縦書き風「食事典」、中央のクリーム色の帯に**店名**、下に本アイコン。
- **詳細画面**：1冊の本を開いた見た目。クリーム色の紙のページを `PageView` で**めくって**いく。
  - **表紙ページ**：店名（金枠）、住所、「収集 X / Y」、本アイコン。
  - **メニューページ**：`3×3` グリッドで**チェキ全体**を並べる。各枠に `No.001` 風の番号＋メニュー名。未収集は「？」の空きチェキ。収集済みをタップすると所持チェキ一覧（横スクロール）。
  - **グループ（封印）ページ**：本の最後。報酬クーポン表示＋**チェキをセットする空き枠（3列）**＋獲得ボタン。

### 3-3. グループ & クーポン
- **グループ** = 店舗が設定する「このメニューを揃えてね」という組み合わせ（例：塩ラーメン3種制覇）。
- ユーザーは自分の**未使用チェキ**を各枠に**手動でセット**する（自動では揃わない）。
- 全枠が埋まると「クーポンを獲得」できる → クーポンコード発行。
- **獲得後はグループがリセット**（繰り返し可能）。使ったチェキには**「使用済」印＋切り込み**が永久に付き、二度と使えない。
- **クーポン画面**：獲得済みクーポンをカードで一覧。提示コードを表示（**会津コイン連携**は店舗端末での提示・支払い想定。アプリ側はコード表示まで）。

## 4. 2種類のユーザー（アカウント種別）

サインアップ時に選択：
1. **一般ユーザー（user）**：タブは **マップ / 辞典 / クーポン** の3つ。チェキを集めてクーポンを獲得する側。
2. **飲食店オーナー（owner）**：**店舗（オーナー）タブのみ**。店舗情報・メニュー・グループ・クーポンを登録/編集する側。

ロールは `profiles.role` に保存され、ルーティングガードで表示エリアを出し分ける。

| タブ/画面 | 内容 |
|---|---|
| **マップ**（map） | flutter_map + OpenStreetMap。登録店舗をピン表示。会津の地図から店を探す。 |
| **辞典 一覧**（dictionary list） | 本棚＝店舗が「閉じた辞典」として並ぶ。 |
| **辞典 詳細**（dictionary detail） | 本を開いてページめくり。チェキ収集・グループ達成の中心画面。 |
| **カード作成/再撮影**（card editor） | 写真（本番はその場でカメラ撮影）＋コメント＋星評価を入力してチェキ化。 |
| **クーポン**（coupons） | 獲得済みクーポンを一覧・コード提示。 |

## 6. 画面一覧（オーナー側）

| 画面 | 内容 |
|---|---|
| **オーナーホーム** | 自店舗の管理ハブ。 |
| **店舗登録/編集** | **地図から店舗の位置をピンで選択**（タップ→逆ジオコーディングで住所自動入力、現在地ボタン、住所検索）。約30m圏の来店判定に使う座標を登録。 |
| **メニュー管理** | 料理（辞典の中身）を登録。 |
| **グループ管理 / グループ編集** | コンプ対象のメニュー組み合わせ＋報酬クーポンを作成・編集・削除。 |

## 7. 主要ルール（ゲーム的制約）

- **来店ジオフェンス**：チェキはその店舗の**約30m以内に実際にいるとき**だけ作成可能（PostGIS `ST_DWithin`）。※本番のみ強制、テストはスキップ。
- **その場撮影**：本番は写真添付ではなく**カメラ撮影**のみ。※テストはギャラリー添付も可。
- **1日1枚/店舗**：同じ店舗では1日1枚（JST基準）。ただし**その日作った分は再撮影OK**。※本番のみ。テストは何枚でも可。
- **同一メニュー複数枚OK**：同じ料理でも（日をまたげば）複数チェキを所持できる。
- **グループは手動セット＆リセット式**：自動では揃わない。獲得後リセット。使用チェキは刻印されて再利用不可。

## 8. 技術スタック（参考）

- **フロント**：Flutter（web-first）, go_router, google_fonts。地図=flutter_map+latlong2, 位置=geolocator, 画像=image_picker, 逆ジオコーディング=Photon（photon.komoot.io）。
- **バックエンド**：Supabase（Postgres + PostGIS, RLS, Auth, Storage）。チェキ写真は `card-photos` バケット。
- **環境分岐**：`kReleaseMode` で本番/テストの挙動を切替（`AppConfig`）。
